# HorneroOS Plugins — official extensions marketplace

First-party extensions for Hornero Shell, plus the curated catalogue
the Shell and `horneroctl` use for discovery. Hornero 199X identity,
real software, no fake screenshots.

## Trust model (read this first)

Quickshell QML runs with **your user privileges**. Hornero Shell does
**not** sandbox plugins, and no manifest can change that. Therefore:

| Trust | Meaning |
| --- | --- |
| `official` | Ships from this repository, reviewed by HorneroOS maintainers, pinned by commit + SHA-256 in `catalog.json`. Still runs unsandboxed. |
| `community` | Third-party code listed for discovery (future). Never reviewed as safe; read the source before enabling. |

Enabling any plugin is an explicit user action (`horneroctl plugin
enable <id> --yes` or the Control Center consent dialog). Installing
only copies inert package data.

Patterns studied and credited: Noctalia's authoritative per-plugin
manifest + generated catalog with pinned revisions, DankMaterialShell
registry's capability disclosure and moderation rules, Ryostore's
category/schema discipline, Omarchy's registry index. GPL-licensed
references (Caelestia) were studied for ideas only; no code is copied
from them. Unlicensed references were treated as study-only.

## Layout

- `plugins/<id>/` — one extension: `manifest.json`, QML entrypoint,
  `README.md`, `LICENSE`.
- `catalog.json` — generated by `scripts/gen_catalog.py`; never edit
  by hand. Installers verify the payload SHA-256 from it.
- `schema/plugin-manifest.schema.json` — the shell manifest contract
  (kept in sync with HorneroOS/shell; the shell copy is canonical).
- `templates/starter-plugin/` — copy this to start a new extension.
- `docs/` — contributor guide, security model, review process.

## Quick start (users)

```sh
horneroctl plugin catalog --json          # browse the official catalogue
horneroctl plugin catalog install hornero-pomodoro --dry-run
horneroctl plugin catalog install hornero-pomodoro --yes
horneroctl plugin enable hornero-pomodoro --yes
```

Or browse and enable from Control Center → Extensions.

## Quick start (authors)

```sh
cp -r templates/starter-plugin plugins/my-plugin
# edit manifest.json + Main.qml
python3 scripts/validate_plugins.py
python3 scripts/gen_catalog.py
```

Validate locally against a real shell before opening a PR:

```sh
horneroctl plugin validate ./plugins/my-plugin
horneroctl plugin install https://github.com/<you>/my-plugin.git --dry-run
```
